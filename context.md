### Deviations from the PDD and why

- **POC service topology:** the target PDD describes separate tenant, ingestion, metering, billing, and optional notification services. Phase 0 deliberately used the POC-prescribed two-service proof: ingestion-service plus combined metering-billing-service, with one seeded tenant/plan/resource and no notification service. This is Phase 0 scope reduction, not a change to the target architecture.
- **Deferred full-design behavior:** the PDD's Redis token-bucket ingestion rate limiter, nightly scheduled Redis reconciliation job, and Quartz/scheduled period-close billing were not implemented. Phase 0 instead proves API-key protection, exact Redis/PostgreSQL reconciliation in integration tests, and an explicit idempotent REST-triggered billing run. These remain later-phase work and do not revise the PDD design.
- **Schema clarification:** `invoice_line_item.tenant_id` was added even though the PDD's abbreviated entity field list omits it, because the same PDD requires every tenant-scoped table to carry `tenant_id` and be protected by RLS. This strengthens conformance to the isolation architecture.
- **Branch/PR history:** implementation was split into cumulative feature branches and draft PRs (`codex/ci-bootstrap` PR #1, `codex/tenant-rls` PR #2, `codex/usage-metering` PR #3, and `codex/tiered-billing` PR #4), followed by the current `codex/auth-live-dashboard` closeout branch, instead of a single linear commit history. This was requested to give CI and review an auditable gate per risk area; it changes delivery workflow only.
- **Build tooling:** Maven 3.9.11 was selected for the Java 21 multi-module reactor because the PDD does not prescribe Maven or Gradle. CI and Docker images compile for/run Java 21. The Windows host verification JVM reported Java 26 but compiled with `--release 21`; this was a local runner difference, not a runtime or architecture change.
- **Windows Docker/Testcontainers workaround:** Testcontainers could not reach Docker Desktop's Windows named pipe from an initially attempted Linux Maven container, so integration tests ran with the workspace-local Maven distribution on the Windows host. Chrome/Angular gates were rerun outside the filesystem sandbox after Windows `EPERM`/GPU-cache failures. No product assertion was waived, and CI remains native Ubuntu with Testcontainers.
- **Local port/exposure workaround:** an unrelated existing Redpanda owned host port 8081 and an unrelated PostgreSQL owned host port 5432. The ingestion container still listens on its designed internal port 8081 but is published locally as configurable host port `8181`; PostgreSQL, Redis, and Redpanda are reachable only on the Compose network. Both Spring services still use Compose DNS and the PDD data flow is unchanged.
- **Loopback/CORS workaround:** local browser verification required both `http://localhost:4200` and `http://127.0.0.1:4200`; CORS is restricted to those two explicit SPA loopback origins. Frontend service URLs were normalized to `127.0.0.1`, and the JWT interceptor was fixed to exclude the API-key ingestion endpoint on host port 8181. This changes local addressing only.
- **Angular cache workaround:** Angular CLI workspace caching was disabled because Windows repeatedly denied access to generated cache/output files. Production optimization, tests, and CI gates remain enabled.
- **Documentation extraction workaround:** `pandoc` was unavailable, so the read-only DOCX source documents were extracted with the bundled `python-docx` runtime into Markdown for review. The authoritative DOCX files were not edited.

None of these deviations changes the architecture described in the PDD itself. They are Phase 0 scope choices, schema enforcement details, review workflow changes, or local Windows execution workarounds. The target PDD architecture remains the declared Phase 1+ direction and was not rewritten during this task.
